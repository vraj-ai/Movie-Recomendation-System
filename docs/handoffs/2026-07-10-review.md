## Tests that were red at the start

The pinned regression gate **`.venv/bin/pytest -q` could not even collect** —
`ModuleNotFoundError: No module named 'recsys'`. Nothing put the repo root on
`sys.path` under the bare `pytest` console script; the "145 passing" from `/coder`
only held via `python -m pytest` (which injects cwd). **Every per-area
verification command was effectively red under the pinned gate.** This was
finding #1.

## Four-net audit — full findings

- **Net 1 — failing tests:** BUG-1 above (gate uncollectable under `pytest`).
- **Net 2 — static (`py_compile`):** clean.
- **Net 3 — invariant violations:** **BUG-2 (SEC-1 key leak).**
  `tmdb.py`'s FAIL-2 `RequestException` branch logged the raw exception, and
  `requests` embeds `?api_key=<KEY>` in its exception string → the key reached the
  logs. **Missed by the `/coder` red-team** (their "key not logged" test only
  exercised the HTTP-500 path, not the connection-error/JSON-decode path).
- **Net 4 — weak/uncovered tests:** **BUG-3.** `split.holdout_split` crashed with
  a cryptic `ValueError: No objects to concatenate` on a *non-empty* dataset where
  every user has <2 ratings (`/coder` only guarded the fully-empty case). The
  SEC-1 `RequestException` path was also untested (folded into BUG-2's fix).
- **Checked and CLEAR:** the metric math in `evaluate.py` (Precision@K, Recall@K,
  NDCG@K, RMSE, MAE) was hand-verified against the tests — correct, no bug.

## Honest follow-ups (deliberately deferred, not papered over)

All are **pre-existing** (from `/coder`), out of this diff's scope, kept explicit:

1. **FAIL-7 cache value-type validation** — `_load_cache` checks required keys
   *exist* but not their value *types* (e.g. `genres` as a string, `keywords` as
   an int). A structurally-present-but-wrong entry is served verbatim. Downstream
   coercion prevents crashes; strengthening is defense-in-depth. *Recommended next
   review target.*
2. **FAIL-3 unbounded `Retry-After`** — a huge 429 header → long `time.sleep`;
   should be capped.
3. **`_extract_features` duplication** — five near-identical try/except blocks
   (refactor smell; also #2/#7 of the `/coder` deferred smell list).
4. **Zero-relevant-item users** included in per-user metric averages — deflates all
   models uniformly, so the *relative ranking* (the deliverable) is undistorted;
   low value.
5. **Duplicate `(userId, movieId)` rows** summed in the CSR matrix on load — no
   dups in `ml-latest-small`; dedup policy is a spec decision.
6. **No linter configured** — only `py_compile`. Adding `ruff`/`flake8` would give
   the static net real teeth. Infra gap, not fixed mid-review.

Plus the 7 refactor smells from the `/coder` handoff remain open (a dedicated
refactor ticket via `/planner` → `/coder` is the clean path for those).
